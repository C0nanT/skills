# Resumo: tdd

**O que faz:** orienta o desenvolvimento orientado a testes no ciclo vermelho → verde. Define o que é um bom teste (comportamento pela interface pública, não pela implementação), onde os testes ficam (**seams** acordados antes de escrever qualquer teste), os anti-padrões (acoplamento à implementação, testes tautológicos, fatiamento horizontal) e as regras do ciclo (fatias verticais, um teste por vez).

**Quando usar:** quando você quer construir funcionalidades ou corrigir bugs escrevendo o teste primeiro, ou quer testes de integração bem desenhados.

**Como invocar:** `/tdd`, ou o agente pode chamá-la sozinho quando a tarefa pedir TDD ou testes de integração (sem `disable-model-invocation`).

**Arquivos:** `SKILL.md` (original em inglês), `TRADUCAO.pt-BR.md` (tradução) e este `RESUMO.md`.
